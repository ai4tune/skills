# 公众号写作风格指南

## 🚫 写作反面教材（必须避免）

### 报告体 → 要改成故事体

**❌ 反面示范**（干巴巴的报告体）：
```
一、系统概述
OpenClaw 是一个智能体平台。具有以下特点：
1. 会拆解任务
2. 会寻找证据
3. 会交付结果

二、变现方式
以下是6种常见的变现方式：
1）内容变现：选题→搜集→成稿
2）ToB接单：方案/标书/PPT
...
```

**✅ 正面示范**（有场景感的故事体）：
```
昨晚十一点，我盯着空白的编辑器发呆——明天要交的方案还没动笔。

我做了一件以前绝对不敢做的事：把这个活直接丢给了小龙虾。

"帮我写一份 SaaS 产品竞品分析报告，覆盖三个头部玩家，要有数据对比表。"

二十分钟后，我收到了一份 3200 字的报告，附带 3 张对比表格和 12 条数据来源链接。

不是那种 AI 味儿的废话堆砌，是那种——你拿去改改就能发给甲方的东西。

那一刻我突然意识到：**这玩意儿不是聊天工具，这是变现工具。**
```

### 关键区别

| 维度 | ❌ 报告体 | ✅ 故事体 |
|------|----------|----------|
| 开头 | "本文将介绍..." | 一个场景/一句话钩子 |
| 论述 | "首先...其次...最后..." | 你遇到过这样的情况吗？→ 我试了一下 → 结果是... |
| 数据 | "数据显示，增长率为 35%" | "35%——这是我看到这个数字时，手抖了一下" |
| 结尾 | "综上所述，建议..." | 一句话点睛 + 引发讨论 |
| 人称 | 第三人称旁观 | "我" "你"直接对话 |
| 节奏 | 长段落+平铺直叙 | 短句爆破+长句缓冲交替 |

### 六个必须避免的写作病

| # | 病症 | 表现 | 药方 |
|---|------|------|------|
| 1 | **列表病** | 全文都是 1. 2. 3. 清单 | 每 3 个要点包裹 1 个故事/场景 |
| 2 | **概念病** | 空讲概念不给体感 | 每个概念配一个 "比如说..." |
| 3 | **无感病** | 通篇没有情绪波动 | 每 500 字至少有 1 个情绪触发（惊讶/共鸣/愤怒/好笑） |
| 4 | **端着病** | 写得像论文或官方通稿 | 用"你"替代"用户"，用口语替代书面语 |
| 5 | **注水病** | "众所周知""不言而喻" | 删掉所有不提供新信息的句子 |
| 6 | **头重病** | 开头铺垫 200 字才进入正题 | 3 行之内必须出现钩子 |

## 📐 公众号排版规范

> ⚠️ **严禁使用 HTML / CSS / style / div 标签！**
> 公众号编辑器只支持 Markdown 原生排版元素。所有排版必须使用纯 Markdown 语法。

### 文章结构

```
标题
摘要
正文（含强调块 + 信息卡片 + 章节标题）
小结
```

### 段落规则

| 规则 | 要求 |
|------|------|
| 段落长度 | **每段不超过 3 行**（移动端核心规则） |
| 重要句子 | **单独一行**，前后各一行空行 |
| 强调块 | 每 3 段插入一个强调块（见下方格式） |
| 列表 | 多使用列表拆分密集信息 |
| 空行 | 段落之间必须有一行空行 |

### 强调块格式（每 3 段用一个）

三种强调块，根据内容性质选择：

**观点强调**：
```
🔥 观点
> 你卖的不是文字，你卖的是确定性。

```

**重点强调**：
```
⚠️ 重点
> 大纲未确认前，绝不进入写作阶段。

```

**提示强调**：
```
📌 提示
> 封面图比例必须是 21:9，否则在信息流中会被裁切。

```

### 信息卡片格式

用于归纳场景、步骤、要点等结构化信息：

```
📌 [场景/步骤/要点名称]
- 要点 1
- 要点 2
- 要点 3

```

**示例**：
```
📌 内容变现的三个核心要素
- 稳定的交付节奏（每周固定篇数）
- 可复用的内容模板（降低单篇成本）
- 清晰的客户画像（知道写给谁看）

```

### 章节标题格式

用 emoji + 分隔线制造视觉节奏：

```
———
🧭 [小标题内容]
———

```

**示例**：
```
———
🧭 为什么说它比"聊天机器人"更有用
———

```

### 排版节奏公式

```
正文段落（≤ 3 行）

正文段落（≤ 3 行）

正文段落（≤ 3 行）

🔥 观点
> [核心观点——制造视觉停顿]

正文段落（≤ 3 行）

正文段落（≤ 3 行）

[📷 AI配图]

正文段落（≤ 3 行）

📌 [信息卡片]
- 要点 1
- 要点 2
- 要点 3

———
🧭 [新章节标题]
———

正文段落（≤ 3 行）
...
```

### 完整排版示范

**❌ 错误排版**（文字墙+报告体+无格式）：
```
一、OpenClaw 的变现方式概述
OpenClaw最常被用来做内容变现。具体来说就是从选题到搜集素材再到拟大纲最后成稿排版分发。你卖的不是文字而是稳定交付。另一个常见的方式是ToB接单，也就是方案标书PPT的初稿。很多小团队缺的是能把资料变成结构化方案的人。智能体擅长做第一版包括框架要点表格风险清单。
```

**✅ 正确排版**（3行段落+强调块+信息卡片+章节标题）：
```
昨晚 11 点，我盯着空白的编辑器发呆。

明天要交的方案——还没动笔。

我做了一件以前绝对不敢做的事：把这个活直接丢给了小龙虾。

🔥 观点
> 二十分钟后，3200 字的报告交到我手上。不是 AI 味儿的废话堆砌，是能直接发给甲方的东西。

那一刻我意识到：

**这玩意儿不是聊天工具，这是变现工具。**

[📷 AI配图 | 风格：扁平插画 | 内容：一个人看着屏幕上自动生成的文档 | 色调：暖橙]

———
🧭 方式一：内容变现——把一篇文章变成流水线
———

不是"写得好"值钱。

是"交付得稳"值钱。

想象一下：客户付你 **月费 3000**，你每周三下午给他一篇 2000 字的行业分析。雷打不动。

📌 内容变现的核心要素
- 稳定的交付节奏（每周固定篇数）
- 可复用的内容模板（降低单篇成本）
- 清晰的客户画像（知道写给谁看）

⚠️ 重点
> 你卖的不是文字，你卖的是「确定性」。

———
🧭 方式二：ToB 接单——方案/标书/PPT
———

很多小团队缺的不是想法，是这样一个人：

- 能把 30 页资料压缩成 5 页方案
- 能把客户的需求翻译成结构化文档
- 能在 3 小时内交出一份"能看"的初稿

小龙虾就是这个人。
```

### 格式禁令

| 禁止项 | 原因 |
|--------|------|
| ❌ HTML 标签 | 公众号编辑器不稳定支持 |
| ❌ CSS 样式 | 会被公众号编辑器过滤 |
| ❌ style 属性 | 同上 |
| ❌ div 标签 | 同上 |
| ❌ 标题中的 emoji | 公众号标题不显示 emoji |
| ❌ 超过 3 行的段落 | 移动端阅读不友好 |
| ❌ 连续 3 个以上感叹号 | 低质感 |
| ❌ 「震惊体」开头 | 低质感 |

**只使用公众号原生支持的排版**：Markdown 加粗、引用块、列表、分隔线、emoji。

## 🖼️ AI 配图规范

### 配图位置规则

| 位置 | 说明 | 建议 |
|------|------|------|
| **封面图** | 信息流中决定点击率的第一要素 | 21:9 比例，有视觉冲击力 |
| **开头后** | 第一段结束后插入第一张配图 | 呼应开头场景或情绪 |
| **每 500-800 字** | 正文中每 500-800 字插一张 | 呼应当前段落主题 |
| **金句旁** | 重要金句前/后 | 增强传播力 |
| **结尾前** | 文章收束前 | 回扣主题或情绪升华 |

### 配图风格指引

| 文章品类 | 推荐风格 | Prompt 关键词 |
|----------|---------|---------------|
| 行业干货 | 扁平插画、信息图 | flat illustration, infographic, minimalist |
| 商业分析 | 数据可视化、商务场景 | business, data chart, modern office |
| 情感共鸣 | 摄影风、温暖色调 | warm tone, lifestyle photography, soft light |
| 科技科普 | 未来感、抽象几何 | futuristic, abstract geometry, tech |
| 故事型 | 场景插画、叙事性 | scene illustration, storytelling, narrative |

### 配图描述格式

在正文中用以下格式标记需要插图的位置：

```
[📷 AI配图 | 风格：扁平插画 | 内容：一个人对着电脑屏幕发呆，旁边是一只小龙虾在自动打字 | 色调：暖橙色]
```

AI 读取到此标记时应：
1. 调用图片生成 API 生成配图
2. 将图片上传到公众号素材库
3. 在正文中对应位置插入图片

## 口吻参数

| 风格 | 人称 | 语气 | 句式特征 | 适用场景 |
|------|------|------|----------|----------|
| **干货型** | 我/你 | 专业但不端着 | 短句多、数据密、结论先行 | 行业分析、工具评测、方法论 |
| **故事型** | 第三人称/我 | 娓娓道来 | 场景描写、对话还原、时间线叙事 | 人物故事、品牌故事、经验复盘 |
| **争议型** | 你/我们 | 犀利、直接 | 设问反问、对比冲突、立场鲜明 | 观点输出、热点评论、行业辩论 |
| **情绪型** | 你/我 | 温暖/愤怒/焦虑 | 感叹句多、排比、金句感强 | 生活感悟、情感共鸣、焦虑话题 |
| **科普型** | 我们 | 亲切、耐心 | 类比解释、FAQ 结构、循序渐进 | 知识科普、概念解读、入门指南 |

## 禁忌清单

### 广告法高风险词（绝对化用语）

❌ 禁止使用以下词汇及其变体：

| 类别 | 禁用词 |
|------|--------|
| 绝对化 | 最、第一、唯一、首个、顶级、极致、绝对 |
| 虚假承诺 | 保证、包治、根治、100%、永不、必定 |
| 权威误导 | 国家级、世界级、全网、全民、获奖（无证据） |
| 诱导用语 | 秒杀、疯抢、最后机会、错过再等一年 |

### 内容红线

- ❌ 不传播未经证实的医疗/健康建议
- ❌ 不使用歧视性语言（性别、地域、职业、外貌）
- ❌ 不编造虚假案例或数据
- ❌ 不进行无标注的商业推广
- ❌ 不使用版权不明的图片/文字

## 默认配置

当用户未指定风格时，使用以下默认值：

```yaml
style: 干货型
person: 你/我
target_length: 1500-2500
paragraph_max_lines: 3              # 每段最多3行
emphasis_block_frequency: 3          # 每3段一个强调块
image_frequency: "每500-800字一张"
must_include:
  - headline_variants: 3
  - summary: true
  - golden_quotes: 2
  - call_to_action: true
  - source_references: true
  - ai_images: "3-5张（含封面）"
  - emphasis_blocks: "🔥/⚠️/📌"
  - info_cards: "📌 场景"
  - section_dividers: "——— 🧭 ———"
must_avoid:
  - report_style: true
  - html_tags: true               # 严禁 HTML
  - css_styles: true              # 严禁 CSS
  - div_tags: true                # 严禁 div
  - consecutive_lists: 5
  - long_paragraphs: 3            # 段落不超过3行
  - concept_without_example: true
```
