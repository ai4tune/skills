# 公众号全流程编排技能

接收用户一句话自然语言指令，自动编排完整的公众号内容创作流水线。支持标准模式和移动端极简模式。

Read [references/flow-diagram.md](references/flow-diagram.md) 获取流水线流程图和节点说明。

## 核心理念

> **编排技能的职责不是"把事情都做完"，而是：**
> 1. 把用户一句话拆成结构化意图
> 2. 按顺序调用子技能
> 3. 在关键节点暂停给用户挑选/确认
> 4. 把发布作为可选最后一步（默认停在草稿/导出）

## 📱 移动端极简模式（5+10+2 分钟）

专为手机操作和碎片化创作设计。全程支持语音输入，最小化文字交互。

### 体验目标

```
☀️ 早上起床（5 分钟）
  → 看热点推荐或语音说选题 → 选一个编号

🚗 通勤/碎片时间（10 分钟）
  → AI 自动采集+写作 → 你对话润色修改

🛋️ 睡前/间隙（2 分钟）
  → 手机端打开公众号助手 App → 预览 → 确认发布
```

### 进入方式

以下指令自动进入移动端模式：

- "手机模式"/ "移动模式" / "极简模式"
- "快速出稿"
- "5 分钟搞定今天的推文"

### 移动端模式特性

| 特性 | 标准模式 | 📱 移动端模式 |
|------|---------|-------------|
| 交互轮次 | 5-7 轮 | **≤ 3 轮** |
| 选题展示 | 5-10 个完整卡片 | **3 个精简卡片**（标题+推荐指数） |
| 大纲确认 | 完整展示 | **一句话概要**，回复"OK"即可 |
| 文章展示 | 完整展示 | **只展示开头+结尾+自检分数** |
| 语音友好 | 一般 | **优化**（短句指令、数字编号操作） |

### 移动端流程

```
📱 极简流程（3 轮交互）

第 1 轮（5 分钟）：
  用户："[语音] 帮我写一篇关于 AI 编程工具的推文"
  AI：展示 3 个选题（只显示标题+⭐），等回复编号

第 2 轮（10 分钟）：
  用户："1"
  AI：自动执行 → 大纲确认+素材+写作 → 展示文章摘要+自检分
  用户："把开头改得更抓人一点"（可选润色）

第 3 轮（2 分钟）：
  用户："进草稿"
  AI：创建草稿 → 提示打开公众号助手 App 预览发布
```

## 两种入口方式

### 入口一：手动触发（一句话指令）

用户提供一句话自然语言指令，例如：

- "帮我写一篇关于 OpenClaw 小龙虾的公众号文章"
- "给我的 AI 工具评测号做一期内容，要干货风格"
- "下周端午节，帮我策划并写一篇推文，直接进草稿箱"

### 入口二：热点推荐触发

用户收到 `wechat-topic` 的定时热点推荐后，直接回复编号，自动进入后续流程：

```
🔔 今日热点选题推荐（07:00）
1. 🔥 Claude 发布新模型
2. ⏰ OpenAI 调整定价
3. 📅 AI 编程工具报告

用户回复："1"
→ 自动进入阶段 3（内容方案 Brief）→ 后续全自动
```

编排技能将自动解析为结构化意图：

| 维度 | 解析方式 |
|------|----------|
| 主题 | 从指令中提取核心话题 |
| 受众 | 根据话题推断或使用默认值 |
| 品类 | 匹配内容品类矩阵（支持叠加） |
| 风格 | 从指令中识别或使用默认值（干货型） |
| 目标 | 识别流程终点（选题/成稿/草稿/导出/发布） |
| 频率 | 从上下文推断或忽略 |

## 编排流程（7 阶段）

### 阶段 1：意图解析

```
用户一句话 → 结构化参数
```

- 解析用户指令，提取主题、受众、品类、风格、目标等维度
- 自动匹配内容品类矩阵（可叠加）
- 对缺失维度做合理推断
- 输出结构化参数卡片，让用户确认

**输出示例**：
```
📋 意图解析结果：
- 主题：OpenClaw 小龙虾品牌
- 品类：商业分析 + 生活方式
- 受众：餐饮从业者 / 美食爱好者（推断）
- 风格：干货型（默认）
- 目标字数：1500-2500 字（默认）
- 流程终点：创建草稿（默认）

确认以上参数？或告诉我需要调整的部分。
```

### 阶段 2：选题生成 → 🛑 必停点

```
调用 wechat-topic → 展示 3-10 个选题 → 等待用户选择
```

- 调用 `wechat-topic` 技能生成选题（如从热点入口则跳过此步）
- 展示选题卡片列表（含品类标签、推荐指数和风险标签）
- **🛑 暂停等待用户选择**（用户回复选题编号即可）

**交互示例**：
```
📝 为你生成了 5 个选题，请选择一个：

1. ⭐⭐⭐⭐⭐ [商业分析+情感共鸣] 小龙虾经济学：为什么年轻人愿意花半天工资吃一顿？
2. ⭐⭐⭐⭐ [行业干货] OpenClaw 如何在红海市场杀出一条路？
3. ⭐⭐⭐⭐ [科技科普+生活方式] 一只小龙虾的「前世今生」：从入侵物种到千亿产业
4. ⭐⭐⭐ [商业分析] 小龙虾店为什么总在排队？背后的运营秘密
5. ⭐⭐⭐ [观点输出] 吃小龙虾的社交礼仪：当代年轻人的餐桌文化

回复编号选择，或说「重新生成」获取新选题。
```

### 阶段 3：内容方案 Brief + 大纲确认 → 🛑 必停点

```
用户选定选题 → 生成内容方案 Brief → 展示大纲 → 等待用户确认
```

- 调用 `wechat-topic` 的内容方案 Brief 功能
- 生成文章节奏规划和段落大纲（每段标注钩子类型 🎣🔥💡💬🎯）
- 评估阅读价值
- **🛑 暂停等待用户确认大纲**

**交互示例**：
```
📋 内容方案 Brief：

标题方案：
  A. 小龙虾经济学：为什么年轻人愿意花半天工资吃一顿？ → 数据+悬念
  B. 月薪 5000，却舍得吃 200 的小龙虾，图啥？ → 情绪+共鸣
  C. 200 块一斤的小龙虾，到底收割了谁？ → 争议+好奇

文章节奏：
  1. 🎣 开头钩子：白领排队买小龙虾的场景（10%）
  2. 💡 数据冲击：客单价 vs 收入数据（20%）
  3. 🔥 高潮分析：三个消费心理深度拆解（30%）
  4. 💬 案例金句：品牌定价策略案例（25%）
  5. 🎯 行动引导：反思金句 + 留言互动（15%）

阅读价值：⭐⭐⭐⭐⭐（值得写）

确认大纲？或说「调整 [段落编号] [修改意见]」
```

> ⚠️ **大纲未确认前，不允许进入素材采集和正文写作阶段。**
> 这是为了避免写到一半才发现方向错误。

### 阶段 4：素材采集 → 自动执行

```
确认大纲 → 调用 wechat-research → 自动采集素材
```

- 调用 `wechat-research` 技能
- 按选题和大纲自动规划来源策略并采集素材
- 展示素材采集摘要（不逐条展示，避免信息过载）
- **默认不暂停**，除非素材不足需用户补充

**输出示例**：
```
📚 素材采集完成！
- 高可信素材：4 条
- 中可信素材：3 条
- 低可信素材：1 条
- 覆盖大纲段落：5/5 ✅

正在进入写作阶段...
```

### 阶段 5：文案生成 + AI 配图 → 可选停点

```
选题 + 大纲 + 素材 → 调用 wechat-write → 生成文章（含配图）+ 自检报告
```

- 调用 `wechat-write` 技能
- 使用锁定的大纲和采集的素材
- **强制故事体写作**（禁止报告体），严格执行排版规范
- **自动生成 AI 配图**（每 500-800 字 1 张，长文至少 3 张）
- 生成完整文章并附带五维度自检报告
- **可选暂停**：展示文章和自检得分

**输出示例**：
```
📄 文章已生成！

标题：小龙虾经济学：为什么年轻人愿意花半天工资吃一顿？
字数：2136 字
版本：长文
配图：4 张（1 封面 + 3 正文插图）

[完整文章内容，含排版和配图标记]

---

📋 自检得分：42/50 ✅
- 📊 信息密度：8/10 ✅
- 🎯 标题吸引力：9/10 ✅
- 💡 金句质量：7/10 ✅
- 📱 排版友好度：9/10 ✅
- ⚖️ 合规安全：9/10 ✅

📸 配图状态：4/4 已生成 ✅

✅ 满意 → 回复「进草稿」创建草稿 / 回复「导出」保存为文件
✏️ 修改 → 告诉我需要调整的部分
🔄 重写 → 回复「重写」换一个风格
🖼️ 换图 → 回复「换图 [位置]」重新生成某张配图
```

### 阶段 6：推送/导出 → 🛑 必停点

```
确认文章 → 调用 wechat-publish → 封面图生成 + 创建草稿或导出文件
```

- 调用 `wechat-publish` 技能
- **自动生成封面图**（21:9 比例，根据文章品类匹配风格）
- **默认创建草稿**（不直接发布）
- 可选导出为标准化 `.md` 文件
- 提示用户通过「微信公众号助手」App 手机端预览和发布

**输出示例**：
```
✅ 已创建草稿！

- 草稿 ID：draft_20240615_001
- 封面图：已自动生成（21:9 商务风格）
- 登录公众号后台即可查看和编辑

📱 手机端操作：
  1. 打开「微信公众号助手」App
  2. 查看草稿 → 预览效果
  3. 确认无误 → 点击发布

📁 同时已导出文件：20240615_小龙虾经济学.md

🔗 更多操作：
- 回复「预览」发送到手机预览
- 回复「定时发布 明天 8:00」设置定时
- 回复「直接发布」需要确认口令
```

### 阶段 7（可选）：多版本生成

```
回复「朋友圈版」或「口播版」→ 自动生成其他版本
```

- 基于已生成的长文版本精炼
- 无需重新采集素材
- 各版本独立导出

## 快捷模式

如果用户指令中包含明确的速度标记，可跳过部分交互：

| 标记 | 行为 |
|------|------|
| "快速" / "直接" | 跳过意图确认，选题使用推荐指数最高的 |
| "草稿" | 全流程自动（保留大纲确认），最终进草稿 |
| "帮我选" | AI 自动选择推荐指数最高的选题 |
| "用上次的风格" | 复用上次的风格配置 |
| "导出" | 全流程自动，最终导出为本地 `.md` 文件 |
| "手机模式" / "极简" | 进入移动端极简模式（3 轮交互） |
| "今日热点" | 从热点推荐入口开始，跳过意图解析和选题生成 |

## 每日自动化工作流（CronJob 集成）

支持全自动定时运行，配合 `wechat-topic` 的热点监控实现"起床就有选题"：

```yaml
# 完整日更自动化配置
daily_workflow:
  # 第一步：早上 7:00 自动抓取热点
  hot_topic_cron: "0 7 * * *"

  # 第二步：用户选题后自动执行（约 10 分钟）
  auto_steps:
    - research       # 自动采集素材
    - write          # 自动生成文章
    - self_check     # 自动质量检查
    - cover_image    # 自动生成封面图
    - draft          # 自动进草稿箱

  # 第三步：推送提醒用户审核
  notify: "📱 今天的推文已进入草稿箱，请打开公众号助手 App 预览发布"
```

## 错误处理（静默降级）

> 借鉴 AutoContents 的 silent degradation 模式

| 场景 | 行为 | 绝不做 |
|------|------|--------|
| API 未配置 | 静默跳过该功能，继续执行后续步骤 | ❌ 不报错、不提示用户配置 |
| 封面图生成失败 | 跳过封面，只输出文章 | ❌ 不中断流程 |
| 素材来源不可达 | 标注该来源不可用，用已有素材继续 | ❌ 不因单个来源失败就放弃 |
| AI 配图 API 失败 | 保留 `[📷 AI配图]` 标记，不生成图片 | ❌ 不重试超过 1 次 |
| 子技能超时 | 展示已完成的部分，提供重试选项 | ❌ 不丢失中间结果 |

核心原则：
- 记录每个阶段的中间结果，支持从失败点恢复
- 不因中间失败丢失已完成的工作（如选题、大纲和素材）
- 能降级则降级，不能降级则暂停等用户决定

## 偏好学习（Agent 记忆）

> 借鉴 AutoContents 的 agent-rules.md 自学习模式

编排技能在以下时机自动更新 `wechat-topic/references/style-memory.md`：

| 时机 | 记录内容 |
|------|---------|
| **用户选题后** | 推荐了哪些 vs 选了哪个 → 品类偏好、标题风格偏好 |
| **大纲修改后** | 用户改了什么 → 结构偏好、深浅偏好 |
| **文章修改后** | 用户要求重写哪部分 → 写作风格偏好 |
| **每 5 次选题** | 汇总分析，更新整体偏好规律 |

下次选题时，`wechat-topic` 读取记忆文件，自动调整推荐权重。

## 通知闭环

> 借鉴 AutoContents 的 notify-bot 模式

每个关键阶段完成后，生成结构化进度通知（适合移动端推送）：

```
阶段完成通知格式：

✅ [阶段名] 完成
📋 结果摘要（1-2行）
🔗 下一步操作提示

示例：
✅ 文案生成 + 配图完成
📋 《小龙虾经济学》2136字 | 自检42/50 ✅ | 配图4张
🔗 回复「进草稿」或「修改」
```

## 自检联动

- 如果 wechat-write 的自检总分 < 35（❌ 不达标），编排技能会：
  1. 展示具体扣分项和修改建议
  2. 自动重写低分段落
  3. 重新自检
  4. 仍不达标则暂停等用户决定（继续发 / 修改 / 换题）

## 输出规则

- 每个阶段的输出紧凑简洁，避免信息过载
- 使用 emoji 标记状态（📋📝📚📄✅📱）
- 明确告诉用户下一步需要做什么
- 提供清晰的操作指引（回复什么内容触发什么操作）
- 移动端模式下优先使用短句和数字编号交互
- **结构化输出**：文章按 `output-schema.md` 的段落类型输出，确保下游可靠消费
